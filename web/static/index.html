    The agent

    A customer-support assistant with four tools: search the knowledge base, look up a customer, send an email and issue a refund. It runs on Amazon Bedrock AgentCore Runtime. Its tools sit behind AgentCore Gateway.

    The layers

    1. Model and prompt only (none). The baseline. The model's own judgment is the only protection.
    2. + Bedrock Guardrails (guardrail). Screens the user message for prompt attacks and harmful content, and masks SSNs and card numbers in both the message and the reply. It sees text, not intent.
    3. + Isolation (isolation). Retrieved documents are screened and fenced off as untrusted data, and the system prompt is hardened. It reduces risk but cannot guarantee anything.
    4. + Gateway policy (policy). Cedar rules on the gateway decide whether a tool call is allowed at all (for example, refunds over a limit, or email to an outside domain). This is enforced outside the model, so the model cannot talk its way past it.

    Reading the scoreboard

    • Attack: should succeed against a weak setup. The number you want to see fall is the harm rate.
    • Control: obvious attacks that the model already resists. They show where the baseline is already fine.
    • Benign: legitimate requests. They measure false positives, because a defense that blocks real work is not free.
    • Outcomes are decided by a deterministic check (what the tools recorded, or a planted canary string), never by another model.
    • Runs that crash are excluded from the rates, not counted as a defense holding.

    Honest limitations

    • Model behavior is random. With a few repeats per cell the numbers are noisy. They illustrate, they do not prove.
    • The attack set is small and written for this demo. Passing it says nothing about attacks that are not in it.
    • The tools are simulated. The policy layer is real, but the data and side effects are not.
